# Migration fixtures — captured chains from prior Workspace versions

Each fixture in this directory is a frozen `events.jsonl` written by a specific
historical version of Workspace's `MutationLog`. The migration regression tests
(`../test_chain_format_migration.py`) load each fixture through the *current*
runtime and assert that the chain still verifies (or degrades in a documented,
non-failing way).

These fixtures are the single, load-bearing protection against chain-format
drift across minor versions: the chain format has changed repeatedly
(hash-link in 0.6.5, Ed25519 in 0.6.6, lock hardening + local-LLM
side-effects in 0.6.7). Without these tests, any such change can silently
invalidate every existing user's audit trail on upgrade.

---

## Layout

```
fixtures/
  README.md                  ← this file
  v0_6_5_chain.jsonl         ← 5 events, hash-chained, NO signatures
  v0_6_6_chain.jsonl         ← 5 events, hash-chained + Ed25519-signed
  v0_6_6_pubkey.pem          ← public key used to sign v0_6_6_chain.jsonl
  v0_6_7_chain.jsonl         ← 5 events, same shape as 0.6.6 (no schema delta)
  v0_6_7_pubkey.pem          ← public key used to sign v0_6_7_chain.jsonl
```

A fixture is **a chain**, not a single event. Five events per fixture is the
agreed minimum to exercise: genesis link → typical link → typical link → a
secondary `event` type (e.g. `live`/`supersede`) → final link. More events are
welcome; fewer is not enough to surface position-dependent bugs.

---

## Per-version shape — what each fixture documents

### v0.6.5 — hash chain only

- Each event is a JSON object with the base schema (`event`, `folder_path`,
  `pair_id`, `lifecycle_state`, `channel`, `problem_id`, `source_hash`,
  `actor`, `audit_id`, `ts`, `extra`).
- **New in 0.6.5:** `prev_hash` field. First event = `"GENESIS"`. Each
  subsequent event's `prev_hash` = canonical SHA-256 of the preceding event,
  computed with `sort_keys=True`, compact separators, `ensure_ascii=False`,
  EXCLUDING `prev_hash` and `signature` from the hash input.
- **NOT present:** `signature` field. The Ed25519 layer did not exist yet.
- **NOT present:** `host_id` field.
- `verify_chain()` on a 0.6.5-shape event on current runtime:
  - `legacy_events`: 0 (events have `prev_hash`, so they are NOT legacy in the
    pre-0.6.5 sense — "legacy" means "no prev_hash at all").
  - `unsigned_events`: == total (no signatures present).
  - `broken_links`: 0 (chain links are valid).
  - `signature_failures`: 0 (we don't fail on absent signatures).
  - `ok`: True.

### v0.6.6 — hash chain + Ed25519

- Same shape as 0.6.5 PLUS `signature` field on each event.
- The signature is computed over `_signed_bytes(event_dict)` =
  `f"{canonical_hash}|{prev_hash}".encode("utf-8")` — content + chain
  position, so a signature cannot be lifted from one position and replayed.
- The signature is a hex-encoded Ed25519 signature against the keypair
  generated by `signing.ensure_keypair()` (default location:
  `~/.workspaceversum/keys/identity.priv`).
- **Fixture-specific:** the public key that signed `v0_6_6_chain.jsonl` is
  stored alongside it as `v0_6_6_pubkey.pem`. The test loads this key
  explicitly rather than relying on the runtime to generate a fresh one
  (which would obviously fail verification).
- `verify_chain()` on a 0.6.6-shape chain on current runtime:
  - `legacy_events`: 0
  - `unsigned_events`: 0
  - `broken_links`: 0
  - `signature_failures`: 0 IF the public key matches; else == total.
  - `ok`: True.

### v0.6.7 — no chain-format delta

0.6.7 hardened the lock, added `local_llm_*` tools, and added the
discoverability CLI. It did NOT change the mutation-log schema.
`v0_6_7_chain.jsonl` is therefore identical in shape to v0.6.6 and the test
treats it the same way. We keep the fixture as a deliberate regression boundary
so a later schema-changing patch labelled "minor" still trips a test.

## How to capture a new fixture from a real prior-version install

The stub fixtures in this directory were hand-built to document the schema.
For high-confidence migration testing, replace them with chains captured from
actual prior-version installs. Protocol:

1. **Spin up the prior version in an isolated venv:**
   ```bash
   python3.11 -m venv /tmp/workspace-v0.6.5
   source /tmp/workspace-v0.6.5/bin/activate
   pip install git+https://github.com/Flxk1/workspace.git@v0.6.5
   export WORKSPACEVERSUM_LOG_ROOT=/tmp/workspace-v0.6.5/log
   export WORKSPACEVERSUM_KEY_DIR=/tmp/workspace-v0.6.5/keys
   ```

2. **Drive 5 representative events through the install:**
   ```bash
   mkdir -p /tmp/workspace-v0.6.5/workspace
   cd /tmp/workspace-v0.6.5/workspace
   workspaces ingest README.md           # event 1: ingest/document
   workspaces ingest CHANGELOG.md        # event 2: ingest/document
   echo "a websearch" | workspaces capture-web --query "test"   # event 3: websearch
   echo "an llm exchange" | workspaces capture-llm --prompt "x" # event 4: llm_answer
   workspaces supersede --pair-id <id-of-event-1>               # event 5: supersede
   ```

3. **Copy out the resulting JSONL + pubkey:**
   ```bash
   FOLDER_HASH=$(workspaces status --json | jq -r .folder_id)
   cp /tmp/workspace-v0.6.5/log/$FOLDER_HASH/events.jsonl \
      <repo>/workspace/runtime/tests/migration/fixtures/v0_6_5_chain.jsonl
   cp /tmp/workspace-v0.6.5/keys/identity.pub \
      <repo>/workspace/runtime/tests/migration/fixtures/v0_6_5_pubkey.pem
   ```

   (For v0.6.5, the pubkey copy is a no-op because there are no signatures —
   skip it.)

4. **Re-anchor the events to a tmp folder path** so the test doesn't pin to a
   specific captor's filesystem:
   ```bash
   sed -i '' -E 's|"folder_path":"/tmp/workspace-v0.6.5/workspace"|"folder_path":"<TMPDIR>"|g' \
     <repo>/workspace/runtime/tests/migration/fixtures/v0_6_5_chain.jsonl
   ```
   The test substitutes `<TMPDIR>` for the actual `tmp_path` at load time.

5. **Commit the fixture.** Each fixture is < 5 KB; the JSONL is human-readable;
   diffs reveal schema changes immediately. Do NOT regenerate fixtures
   casually — they are the regression anchor.

## Stub-vs-real fixture status

| Fixture | Status today | Notes |
|---|---|---|
| `v0_6_5_chain.jsonl` | **stub** | Hand-built. Five events with `prev_hash` only. Documents the shape; not captured from a real v0.6.5 install. |
| `v0_6_6_chain.jsonl` + `v0_6_6_pubkey.pem` | **stub** | Hand-built. Signatures generated by a one-off keypair embedded at fixture-build time. |
| `v0_6_7_chain.jsonl` + `v0_6_7_pubkey.pem` | **stub** | Same shape as 0.6.6. |

The stubs are hand-built and sufficient to catch schema drift today. A real
capture from a prior-version venv exercises code paths a hand-built JSONL
cannot (e.g. the actual `os.urandom`-derived audit_ids and the exact
`time.time()` precision).
